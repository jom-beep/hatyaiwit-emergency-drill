# แผนทดสอบกับอุปกรณ์ 4,000 เครื่อง

## เป้าหมายที่ต้องวัด

- จำนวนอุปกรณ์ลงทะเบียนทั้งหมด แยก iOS/Android
- จำนวนเครื่องที่อนุญาต Notification
- ระยะเวลาจากกดประกาศถึง Worker รับคำสั่ง
- ระยะเวลาจาก Queue ถึง Push provider ตอบรับ
- ระยะเวลาที่ผู้ใช้เห็นและกดรับทราบ
- อัตราข้อความล้มเหลว หมดอายุ และ subscription ถูกเพิกถอน
- ความถูกต้องของการส่งเฉพาะ zone

การตอบรับจาก Push provider ไม่เท่ากับผู้ใช้เห็นข้อความ จึงต้องวัดการกด ACK แยกต่างหาก

## รอบทดสอบ

| รอบ | จำนวนเครื่อง | วัตถุประสงค์ |
| --- | ---: | --- |
| Lab | 20–50 | ตรวจฟังก์ชันและสิทธิ์ |
| อาคารนำร่อง | 300–500 | ตรวจ Wi-Fi, iOS PWA และ Android |
| Load 1 | 1,000 | ปรับ Queue concurrency และ dashboard |
| Load 2 | 4,000 | วัด fan-out, retry และ ACK |
| Degraded | 4,000 | จำลอง Wi-Fi บางส่วนล่มและ Push provider ตอบ 429/5xx |

## เงื่อนไขหยุดการทดสอบ

- ระบบแสดงข้อความที่ไม่มีคำว่า “การฝึกซ้อม”
- ส่งผิด zone
- ผู้ไม่มีบทบาท commander เริ่มประกาศได้
- ยุติเหตุได้ด้วยคนเดียว
- Audit log ขาดหาย
- มีอีเมลหรือรายชื่อ commander ปรากฏใน frontend, log หรือ API response

เมื่อพบข้อใดข้อหนึ่งให้คงระบบไว้ใน DRILL mode ปิดการ fan-out และแก้ไขก่อนทดสอบรอบใหม่
